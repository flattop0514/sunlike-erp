# 请假单管理指南 (`leave`)

本文档涵盖请假单的新增、查询、删除及假别计量单位（VOC_CNT）与审核状态实战规则。

---

## 1. 基础命令速查

- **新增请假单**：
  ```bash
  # 方式 A：使用工号与部门
  ./erp_cli leave add -ref-no <参考单号> -yg-no <员工工号> -dep <部门编号> -sz-no <假别代号>

  # 方式 B：使用姓名自动解析（推荐）
  ./erp_cli leave add -ref-no <参考单号> -name <员工姓名> -sz-no <假别代号>
  ```
  如果需要设置复杂的请假时间段或其它自定义字段，使用 JSON 载荷方式：
  ```bash
  ./erp_cli leave add -file <JSON文件路径>
  ```
  *(模板参考：`<SKILL_DIR>/assets/leave_template.json`)*

- **单笔查询请假单**：
  ```bash
  ./erp_cli leave get -no <请假单号>
  ```

- **批量查询请假单**：
  ```bash
  ./erp_cli leave list -start <开始日期_YYYY-MM-DD> -end <结束日期_YYYY-MM-DD> [-dep <部门代号>]
  ```

- **删除请假单**：
  ```bash
  ./erp_cli leave delete -no <请假单号>
  ```

---

## 2. 核心预提交确认规范（必须执行）

在正式调用 `leave add` 写入 ERP 之前，**必须先以结构化形式向用户展示拟提交信息，获得明确确认后再执行命令**：

- 请假人姓名与工号
- 部门代号与名称
- 假别代号（`SZ_NO`）与名称（如 `C03 事假`、`C06 特休`）
- 请假起止时间（`STR_DD/STR_TIME` ~ `END_DD/END_TIME`）
- 请假合计工时/天数（`VOC_CNT`）及换算依据

---

## 3. 请假单实战避坑经验（必读）

- **VOC_CNT（请假合计）单位取决于假别代号的 UT_DAY，不可一律填小时数**：
  - 调用 `./erp_cli sz list` 查看每个假别的 `UT_DAY` 字段（计量单位）：
    - `3` = 按**天**（如 `C06 特休`、`C07 公假`、`C08 丧假`、`C09 婚假`、`C10 产假`）；
    - `5` = 按**小时**（如 `C03 事假`、`C04 病假`、`C05 旷职`）；
    - `4` = 按**次**（如 `C01 迟到`、`C02 早退`）；
    - `1` = 按**次**（如 `C11 忘打卡`、`C12 未打卡`）。
  - **示例**：
    - 特休（年假）请 3 天 $\rightarrow$ `VOC_CNT: "3"`（千万不要写成 24 小时）；
    - 事假请半天 3.5 小时 $\rightarrow$ `VOC_CNT: "3.5"`。
  - **后果**：单位填错会报 `补／特休数不足!`（错误码 10001）等余额校验错误，即使员工实际额度充足。
- **大陆“年假”映射**：用户说“年假”通常对应 ERP 假别 **`C06 特休`**（台湾系命名），提交前建议用 `./erp_cli sz list` 确认。
- **PASS_OK 审核状态**：模板示例为 `"1"`，但实际提交成功后系统会自动置为 `"3"`（无需审核生效状态），无需手动干预。
- **审核流程未配置报错**：若服务端返回 `当前单据别需要走审核流程，现无设置`（10001），优先切换为实际员工账号（如 11001）登录后重试。
