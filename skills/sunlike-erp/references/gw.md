# 外出申请单管理指南 (`gw`)

本文档涵盖外出申请单的新增、查询、删除及缺省地址 `STA_COUN_ID='0'` 等关键规则。

---

## 1. 基础命令速查

- **新增外出申请单**：
  ```bash
  # 方式 A：使用申请人工号
  ./erp_cli gw add -ref-no <参考单号> -sal-no <申请人工号> -dep <部门> -start <开始日期时间> -end <结束日期时间> -travel-by <交通工具> -amt <金额> -rem <备注> -days <天数>

  # 方式 B：使用姓名自动解析（推荐）
  ./erp_cli gw add -name <申请人姓名> -start <开始日期时间> -end <结束日期时间> -travel-by <交通工具> -amt <金额>
  ```
  录入不带默认示例假地址的干净单据时，使用 JSON 载荷方式（推荐）：
  ```bash
  ./erp_cli gw add -file <JSON文件路径>
  ```
  *(模板参考：`<SKILL_DIR>/assets/gw_template.json`)*

- **单笔查询外出申请单**：
  ```bash
  ./erp_cli gw get -no <外出申请单号>
  ```

- **批量查询外出申请单**：
  ```bash
  ./erp_cli gw list -start <开始日期_YYYY-MM-DD> -end <结束日期_YYYY-MM-DD> [-dep <部门代号>]
  ```

- **删除外出申请单**：
  ```bash
  ./erp_cli gw delete -no <外出申请单号>
  ```

## 2. 生成外出申请单注意事项与预提交确认规范（必读）

生成外出申请单前，**必须逐项核对以下关键信息，并向用户展示确认，严禁未经确认静默提交**：

- **出发地地址 `STA_ADR` / 目的地地址 `END_ADR`（非必填）**：出发地和目的地**不是必填项**，用户未提供具体地址时可不填或留空（如仅知道“去北京”），不要反复追问；用户提供了具体地址才填写。
- **⚠️ 出发地 / 目的地省市区代码 `STA_COUN_ID` / `END_COUN_ID`（核心规范）**：
  - 若用户**未提供**“出发地”和“目的地”具体地址/行政区划代码，**必须显式填为 `'0'`（即 `STA_COUN_ID='0'`, `END_COUN_ID='0'`）**；
  - **严禁留空、空字符串 `""` 或 `null`**，否则 ERP 后端在进行区域代号解析或字段约束检查时可能引发异常。
- **预估金额 `AMT`**：没有时询问或建议合理值后请用户确认（如机票+住宿等可给出参考值）。
- **申请人 `SAL_NO`**：没有明确时询问（可用 `-name` 自动解析，但需用户确认人）。
- **订票否 `BOOKING_ID`**：确认是否需要订票（Y/N）。

## 3. 实战避坑经验

- **gw add 命令行方式会带入默认示例值**：命令行参数 `-sta-adr` / `-end-adr` / `-sta-coun-id` / `-end-coun-id` 等参数有默认示例值（吉大水湾路 / 东大街 / 440402 / 110105）。
- **最佳实践**：**用户未提供具体地址时，强烈推荐使用 JSON 载荷方式（`gw add -file`）**：在载荷中将 `STA_COUN_ID='0'`, `END_COUN_ID='0'` 显式赋值，`STA_ADR` 与 `END_ADR` 留空，避免将示例假地址写入 ERP。
