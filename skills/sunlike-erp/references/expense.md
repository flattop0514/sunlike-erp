# 费用报销单管理与完整工作流指南 (`bx`)

本文档涵盖报销单的新增、查询、修改、删除及端到端自动化费用报销实战流程。

---

## 1. 基础命令速查

- **查询费用设定**（报销分组匹配时必用）：
  ```bash
  ./erp_cli bx fee                 # 查询全部费用代号
  ./erp_cli bx fee -fee-id 1005   # 查询单个费用代号
  ```
- **新增报销单**：
  ```bash
  ./erp_cli bx add -ref-no <参考单号> -dep <报帐部门> -usr-no <报帐人员> -acc-no <费用科目> -fee-id <费用代号> -amt <金额>
  ```
  录入多发票号、多表身等复杂结构时，使用 JSON 载荷方式：
  ```bash
  ./erp_cli bx add -file <JSON文件路径>
  ```
- **单笔查询报销单**：
  ```bash
  ./erp_cli bx get -no <报销单号>
  ```
- **批量查询报销单**：
  ```bash
  ./erp_cli bx list -start <开始日期_YYYY-MM-DD> -end <结束日期_YYYY-MM-DD> -dep <部门代号>
  ```
- **修改报销单表头**（只改表头如备注）：
  ```bash
  ./erp_cli bx update -file <仅含MF_BX的JSON文件路径>
  ```
- **删除报销单**：
  ```bash
  ./erp_cli bx delete -no <报销单号>
  ```

## 2. 费用报销端到端工作流（核心必读）

当用户提出“费用报销 / 我要报销 / 报销xx费用”时，严格按照以下 7 步标准工作流执行：

### 第 1 步：检查发票附件
- 若用户未提供任何发票附件（图片 / PDF / 扫描件），直接回复：`必须提供发票附件才能进行报销`，并结束流程，等待用户上传。

### 第 2 步：识别发票并按费用代号分组
- 读取附件内容，提取每张发票的：**发票号码、金额、开票日期/乘车日期、费用性质、购买方名称/税号**。三类发票源提取方法：
  - **文本型 PDF**：直接读取文字提取；
  - **扫描件 PDF（图片型）**：当 PDF 无法直接提取文字时，转为图片后进行多模态视觉识别：
    - Python (PyMuPDF/fitz)：`pix = page.get_pixmap(dpi=200); pix.save("page.png")`
    - 系统 CLI 工具：`pdftoppm -png -r 200 input.pdf page` 或 macOS `sips` / `qlmanage -t -s 1000 -o /tmp input.pdf`
    - 读取渲染出的发票图片提取字段；
  - **数电票 PDF（XML 优先）**：数电票通常内嵌发票 XML。优先尝试提取 XML：
    - 提取方法：Python (PyMuPDF) `doc.embfile_names()` / `doc.embfile_get(name)` 或 pypdf attachments；
    - XML 交叉核验：文件名形如 `rai_issuer_<YYYYMMDD>_<发票号>.xml`（文件名含开票日期与发票号）；XML 节点直接提供 `Fpdm/Fphm`（代码/号码）、`Kprq`（开票日期）、`Jshj`（价税合计）、`Gmfnsrsbh/Gfmc`（购买方税号/名称），用于核对并填充 `INV_NO` 主档。无内嵌 XML 则回退到扫描件转图识别。
- 调用 `./erp_cli bx fee` 查询**当前账套**的费用设定（FEE_ID + NAME），将发票费用匹配到费用代号。
- **⚠️ FEE_ID 账套差异性**：绝不可硬编码 FEE_ID 数字，必须实时 `bx fee` 查询，**按费用代号名称（NAME）匹配**。
- **同一费用代号的多张发票汇总为一笔表身项目**（一个 ITM）。
- 若发票费用无法归属到任何费用代号：列出可能的归属项目 / 费用代号让用户选择，用户确认后才继续。

### 第 3 步：生成表身项目（TF_BX）
每笔表身项目必填字段：
- 金额 `AMT` / `AMTN`：该费用代号下发票金额的汇总（**同一 FEE_ID 的多张发票合并为一笔 ITM**）
- 日期 `SDAY` / `EDAY`：**火车票取「乘车日期」而非开票日期**（票面"乘车日期"字段）；多张发票取**最早 / 最晚**日期。无乘车日期的（停车费、充值等）用开票日期。例：两张动车票乘车日期 01-15、01-17 → SDAY=01-15、EDAY=01-17
- 单据张数 `FORM_CNT`：该笔合并的发票张数汇总（两张票合并一笔 → FORM_CNT=2）
- `FEE_ID` 费用代号、`ACC_NO` 科目（取自费用设定，如 1005→6601 销售费用）
- `ITM` 项次：每笔表身**必须有**（从 1 递增），缺失报 `列"ITM"不允许 nulls`（10001）
- **发票号码 `INV_NO` 必填**：写该笔**第一张**发票号码（单值定长字段，逗号拼接多个号会报 `MaxLength 限制`），同时写 `INV_BIL_ID='BX'`、`INV_BIL_NO=报销单号` —— 三个字段缺一不可，否则**界面发票号码列查不到、发票画面不关联**（留空 = 界面空白）
- 其余发票号码挂「发票号码库」TF_BX_INVNO（见第 4 步）
- `SAL_NO_BX` 请款人工号、`SAL_BX_NAME` 请款人姓名、`DEP`/`DEP_NAME` 部门

### 第 4 步：发票号码库（TF_BX_INVNO）与发票登记主档（INV_NO）
- **发票号码库 `TF_BX_INVNO`**：**每张发票一行**（含已写入表身 INV_NO 的那张），字段 `BX_NO + ITM + INV_NO`。同一 ITM 可插多行、仅 INV_NO 不同（合并一笔挂两张票的场景就在此体现）。**⚠️ `BX_NO` 必须留空 `""`** —— 服务端自动回填；预填单号会报外键约束错误（`ForeignKeyConstraint TF_BXTF_BX_INVNO`）。
- **发票登记主档 `INV_NO`（界面"发票号码库"展示的表）**：**每张发票一条记录**，字段：`INV_NO` 发票号码、`BIL_ID='BX'`、`BIL_NO=""`、`INV_ID`（如 21）、`INV_DD` 开票日期、`INV_YM` 开票年月（YYYYMM）、`UNI_NO_BUY` 购买方税号、`TITLE_BUY` 购买方名称、`AMT` 金额、`TAX`、`SYS_DATE` 当前时间戳（`.000` 结尾）。**必须随单写值**，漏写则界面发票号码库查不到号码。

### 第 5 步：附件入库
- 调用 `./erp_cli file add -bil-id BX -bil-no <报销单号或空> -bil-itm 0 -path <附件路径>` 将发票附件写入**表头附件库**（**默认 BIL_ITM=0 放表头**），记录返回的 FILE_ID 供核对。
- **同步统计附件张数**：每笔表身对应的发票/单据数量将写入表身 `FORM_CNT`（见第 3 步）。

### 第 6 步：生成表头（MF_BX）
- 报销部门 `DEP`：取**登入人员的归属部门** —— 用 `./erp_cli yg get -no <登录工号>` 查询；若登录账号不在员工资料中，则询问用户提供部门
- 请款人 `USR_NO`：**登入人员代号**；请款人姓名/工号同时写入每笔表身 `SAL_NO_BX` / `SAL_BX_NAME`
- 日期 `BX_DD`：**本日**
- 报销明细 `REM`：由 AI **根据表身内容自动汇总**产生（例如："市内交通 100 元、办公用品 50 元"），不是空文本

### 第 7 步：预提交确认（必须获得用户明确同意）
- 调用 `bx add` 之前，先以结构化形式向用户展示拟提交内容：表头（部门 / 请款人 / 日期 / 报销明细）+ 每笔表身（费用代号 / 金额 / 起始-结束日期 / 张数）+ 发票号码清单（表身 INV_NO + 号码库全部号码）+ 附件清单。
- **用户确认后才执行 `./erp_cli bx add`**。
- 用户对内容有异议时（如费用归属、金额、名目、日期），根据用户反馈修改后重新展示，直至用户确认。

## 3. 报销单实战避坑经验（必读）

- **审核流程报错（10001）**：若服务端返回 `当前单据别需要走审核流程，现无设置`，**优先切换为员工账号（如 11001）登录后重试**；若仍报错才属 ERP 单据别审核模版未配置。
- **登录凭证会过期**：接口返回 `登陆凭证无效或已过期`（错误码 20004）时需重新 `login`；网络偶发 `connection reset by peer` 属服务端抖动，重试 2~3 次。
- **JSON 载荷完整性**：`bx add -file` 时 MF_BX / TF_BX / TF_BX_INVNO / INV_NO 各表**必须显式携带 BX_NO / BIL_NO 字段（可为空字符串 ""）**，缺失会报 `列"BX_NO"不允许 nulls`（10001）。
- **PGM 字段必须为 `MONBXWEB`**（模板里的值），写错报 `PGM不存在`（10014）。
- **TF_BX 每笔必须有 `ITM` 项次字段**（从 1 递增），缺失报 `列"ITM"不允许 nulls`（10001）。
- **表身发票三字段必填（发票画面根因）**：`TF_BX.INV_NO` 写**第一张**发票号码，同时写 `INV_BIL_ID='BX'`、`INV_BIL_NO=报销单号` —— 界面发票号码列与画面关联只由单值 `INV_NO` 驱动，**留空则界面查不到号码、无画面**；`INV_NO` 是定长单值字段，逗号拼接多号报 `MaxLength 限制`（10001）。
- **发票号码库 `TF_BX_INVNO` 的 BX_NO 必须留空 ""**：服务端自动回填；预填单号反而报外键约束错误。
- **附件不会随 bx add 自动入库**：即使 JSON 中携带 TF_BX_FILE1，提交后 BIL_FILE_COUNT 仍可能为 0。**必须在 bx add 成功后，用 `file add -bil-id BX -bil-no <单号> -bil-itm 0 -path <附件路径>` 逐张上传**，再用 `file get -table TF_BX_FILE1 -file-id <FILE_ID>` 核验。
- **附件归属默认表头，不传表身**：`file add -bil-itm 0`。默认将所有发票附件挂到表头。
- **改表身日期/内容须删单重建（重要）**：`bx update` 命令行参数会将其余字段重置为默认值；`bx update -file` 带表身又触发外键约束。**改表身唯一可靠路径 = `bx delete -no <单号>` 删原单 → 修改 JSON 重新 `bx add`（单号复用）→ 重新 `file add` 逐张上传附件 → `bx get` 核验**。
- **只改表头（如备注）用 `bx update -file`**：构造 JSON 载荷**只传 MF_BX 表头**。
- **CAS_NO（项目代号）未指明时默认为空字符串 ""**，不要沿用模板示例值（如 190B30A001）。
- **费用科目更新后重开新单**：用户更新费用设定后，重新 `bx fee` 查询，按新科目重新分组发票并生成新单，原单保留。
- **核验（提交后必做）**：`bx get -no <单号>` 检查——表头（`BIL_FILE_COUNT` 附件数、`DEP_NAME`、`SAL_NAME`）+ 表身每笔（`AMT` / `SDAY` / `EDAY` / `FORM_CNT` / `INV_NO` / `INV_BIL_ID` / `INV_BIL_NO`）+ 发票号码库 `TF_BX_INVNO` 行数 + 发票登记主档 `INV_NO` 条数；附件另用 `file get -table TF_BX_FILE1 -file-id <FILE_ID>` 核验。
